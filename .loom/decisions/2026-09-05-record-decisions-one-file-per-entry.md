### 2026-09-05: Record decisions one file per entry, and make the old journal a pointer

- Decision:
  - `.loom/decisions/YYYY-MM-DD-<slug>.md` is the decision journal. One file per
    decision, heading `### YYYY-MM-DD: Title`, created with
    `scripts/decisions.sh new` (or `make decisions-new TITLE=...`), rendered on
    demand with `make decisions`, never regenerated into a committed file.
  - `.loom/40-decisions.md` stays as a pointer page so the ~40 citations in code
    comments, CI banners and docs keep resolving. `scripts/decisions.sh check`
    fails if a dated entry heading appears there again, and runs in `lint:docs`.
  - A decision is amended in its own file with a dated paragraph, never by
    adding a second heading (the check treats that as an append).
- Rationale:
  - After the worklog was split in August, this was the last shared append-only
    file in the repo, and it did to Sprint 5's revival what the worklog did to
    Sprint 3: on 2026-09-04 eight open merge requests each appended one entry,
    and every merge re-conflicted all the others on this file alone. The fix
    that worked was chaining the MRs linearly so a merge could never add an
    entry the MRs above did not already carry — a workaround for a layout.
  - Line-number citations into an append-only file rot as earlier entries are
    amended in place; the retention test's citation already pointed into the
    wrong decision. Date-plus-title citations survive the split unchanged.
- Alternatives considered:
  - Keep one file and rely on union merges. Rejected: the union is mechanical
    only when both sides append; an in-place amendment next to an append is a
    real conflict, and it also leaves conflict markers behind when tooling
    slips, which happened once on 2026-09-04.
  - A committed rendered `40-decisions.md` regenerated by a hook. Rejected for
    the same reason the worklog rejected it: every MR would rewrite the
    generated file and the conflict returns.
  - Move decisions into the worklog. Rejected: the two answer different
    questions ("what happened" vs "what we chose and why") and are cited
    separately throughout the code.
- Consequences:
  - Same-day entries render in slug order rather than authoring order; the date
    is the unit of ordering, as in the worklog.
  - `.loom/32-sprint4-execution-specs.md` and `.loom/33-sprint5-execution-specs.md`
    cite the old file by line number. They are dated artifacts; the pointer page
    records how to reproduce the file they cite (`git show 17d41eabc:.loom/40-decisions.md`).
  - `lint:docs` runs on changes under `.loom/decisions/` and to the pointer page.
