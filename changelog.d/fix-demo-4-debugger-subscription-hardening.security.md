- Close SEC-2026-09-27-1: the workflow debugger (`startDebugSession`) no longer executes actions from caller-supplied YAML — every action is a recording no-op unless named in `FI_FHIR_WORKFLOW_DEBUG_ACTIONS`, and `exec` never runs there; each paused action step carries `action.stubbed` and redacted, bounded `action.inputs`. Debug sessions are bounded per process (`FI_FHIR_WORKFLOW_DEBUG_MAX_SESSIONS`, default 8; `FI_FHIR_WORKFLOW_DEBUG_SESSION_TTL`, default 15m) with `fi_fhir_workflow_debug_sessions` and `fi_fhir_workflow_debug_sessions_total{outcome}`.
- **Behaviour change:** the `exec` action now also requires the command in the deployment-owned `FI_FHIR_WORKFLOW_EXEC_ALLOWLIST` (empty by default, which refuses every command); the workflow YAML `allowlist` can only narrow it.
- Close SEC-2026-09-27-2: `createFhirSubscription` and the other subscription mutations contact only https hosts listed in `FI_FHIR_FHIR_SUBSCRIPTION_ALLOWED_HOSTS` (exact or `*.suffix`; empty by default refuses all with "FHIR subscription destination not allowed"), re-check every redirect, and keep at most `FI_FHIR_FHIR_SUBSCRIPTION_MAX_CLIENTS` (default 32) clients in an LRU.
