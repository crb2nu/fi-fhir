- The tag pipeline's `release:gitlab` job attaches the binaries, the checksums and the Helm chart to the GitLab Release that `loom release cut` already created instead of creating a second one, which release-cli refuses. A tag pushed without a cut still gets a Release named after the tag. Each asset link is added on its own and a link the Release already has counts as attached, so a retried job passes; the image is pinned to `release-cli:v0.24.0`.
