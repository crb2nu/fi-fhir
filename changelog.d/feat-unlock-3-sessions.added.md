- Integration Sessions are resumable work in HL7 intake (.loom/42 E-3). `/hl7?session=<id>` reopens a session and shows its newest run, and the page writes that address as soon as it has a session; Home › Recent session rows open it. A session sidebar reads the session back: runs (`sessionRuns`) with each run's diagnostics (`sessionDiagnostics`), **Show in results** (`sessionRun`), the per-run stream (`sessionRunEvents`) while a run is live, publications, simulations, samples and drafts. **Accept fix** records `acceptDiagnosticFix` from the sidebar and from each Warnings row that came from a session diagnostic (WarningList's `onAcceptFix`; session runs now carry `diagnosticId`/`fixAccepted` on their warnings). **Export…** downloads `exportIntegrationBundle` as `fi-fhir-session-<id>-<UTC time>.json` after a required reason, which the API records with the caller on the append-only export row; the file carries no raw sample text and no parsed patient fields (runs keep status, stages, diagnostics, lineage and event envelopes), and raw sample payloads are offered only when the new `capabilities.phiExport` is reported true (`integration.phi.export`), otherwise the dialog names the missing role or says the grant was not reported. **Archive…** takes a session off Recent and asks for no reason, because the mutation records none.
- `/api/auth/status` reports `capabilities.phiExport` and `missingRoles.phiExport`; `integrationSession(id)` answers `null` (instead of "GraphQL request failed") for an id the tenant's store does not hold.
