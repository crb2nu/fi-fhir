- Definition editor and lifecycle authoring (`.loom/42` E-1). New package `internal/integration/lifecycle/authoring` builds, checks and validates integration definition revisions for both `fi-fhir lifecycle seed` (refactored onto it) and the API; a kill-test proves a definition assembled from compiled connection documents has the same digest and canonical JSON as the seed's for the same inputs. GraphQL gains `integrationDefinitions`, `integrationDefinition`, `integrationRegistryArtifacts`, `validateIntegrationDefinitionDraft`, `createIntegrationDefinitionDraft`, `validateIntegrationDefinition` (REAL for the batch source the replica mounts, STATIC with code `VALIDATION_STATIC`, SKIP with a 16-byte reason), `approveIntegrationDefinition` and `publishIntegrationDefinition`, plus `ConnectionRevision.sourceId`, `destinationClass` and `secretBindingNames`; Secret references are checked with the connection catalog's rules (no key material, no whitespace, bounded count) before an append-only revision is written, and creating an identical revision is idempotent. `/api/auth/status` gains the deployment fact `capabilities.definitionAuthoring` and `missingRoles.definitionAuthoring`; `serve` hosts the validators on its lifecycle catalog and reads `FI_FHIR_LIFECYCLE_VALIDATION_MAX_AGE` (default 300 s). The Studio's `/connections` page gains a Definitions tab (table, Overview/Validation/Release/History, New definition, Validate/Approve/Publish through the reason dialog, a link to Operator to deploy, `?definition=&revision=` deep links). New CI proof `test:definition-authoring`. Documented in `docs/user-guide/connections.md` § Definitions and `docs/operations/CONNECTION-CATALOG.md` § Definition authoring.
