- `/api/auth/status` reports `capabilities.terminologyStore`, true when `serve` composed the terminology mapping store (`internal/api/graphql/capabilities.go`, `server.go`, `resolvers/resolver.go`). The Terminology page reads it through `terminologyStoreCapability` (`ui/src/lib/graphql/accessCapabilities.ts`) and, when it is false, renders "not configured on this deployment" before any GraphQL query instead of a "GraphQL request failed" toast (`ui/src/lib/features/terminology/TerminologyPage.svelte`). Documented in `docs/planning/GRAPHQL-API.md` and `docs/operations/CONNECTION-CATALOG.md`.
